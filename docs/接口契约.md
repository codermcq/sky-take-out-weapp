# 苍穹外卖小程序用户端 — 后端接口契约

> 本文档定义小程序前端期望的后端接口。请按此实现后端（Spring Boot），前端已按此联调。
> 响应格式统一为 `{ code, msg, data }`，`code === 1` 成功，其余失败。与你的 `com.sky.result.Result` 一致。

## 通用约定

- **统一前缀**：用户端接口都在 `/user/**` 下。
- **鉴权**：登录后所有请求在 header 携带 JWT，**header 名固定为 `authentication`**（对应后端 `sky.jwt.user-token-name: authentication`）。
- **登录时机**：进入小程序自动微信登录（`wx.login` 静默取 code → 调登录接口换 token）。
- **未登录识别**：任选其一即可被前端拦截跳登录页——
  - 返回 HTTP 401；或
  - `Result.code=0` 且 `msg` 含 `未登录` / `登录失效`；或
  - `Result.msg` 为 `NOT_LOGIN`
- **分页返回**：`historyOrders` 返回 `{ code:1, data:{ total, records: [...] } }`。

| POST | `/user/order/refund/{id}` | - | 空（申请退款）※原型要求，若未实现前端降级为电话提示 |

**OrderSubmitDTO**（对齐苍穹外卖标准 submitOrderDTO）：
```json
{
  "addressBookId": 1,
  "payMethod": 1,
  "remark": "无接触配送…",
  "estimatedDeliveryTime": "2026-08-03 13:00",
  "deliveryStatus": 0,
  "tablewareNumber": 0,
  "tablewareStatus": 1,
  "packAmount": 3,
  "amount": 45.0
}
```
- `deliveryStatus`：0 立即送，1 预约送
- `tablewareStatus`：0 按餐量供应，1 指定数量
- `tablewareNumber`：指定数量时的份数（tablewareStatus=0 时为 0）
- `packAmount`：打包费（前端按 数量×1元 计算）
- `amount`：订单总金额（商品 + 打包 + 配送6元，前端计算）

**Order**：`{ id, number, status, userId, addressBookId, orderTime, checkoutTime, payMethod, payStatus, amount, remark, phone, address, consignee, estimatedDeliveryTime, orderDetailList: OrderDetail[] }`
- `status`：1待付款 2待接单 3已接单 4派送中 5已完成 6已取消
- `payStatus`：0未支付 1已支付 2退款
- `OrderDetail`：`{ id, orderId, dishId?, setmealId?, name, image?, dishFlavor?, number, amount }`

## 前端行为说明（影响你后端的实现）

1. **历史订单三 tab**：全部订单不带参数；待付款传 `status=1`；退款传 `payStatus=2`。若你的 `historyOrders` 需要支持 `payStatus` 过滤，请实现。
2. **模拟支付**：`payment` 只把订单置为已支付即可，不接真实微信支付。
3. **取消/退款**：前端提供按钮与确认弹框。已接单(3)/派送中(4)状态点击「取消」前端只引导拨打电话（不调接口）；待付款(1)/待接单(2)调 `cancel/{id}`。
4. **再来一单**：`repeat/{id}` 需把该订单的商品重新加入当前用户购物车。
5. **省市区**：前端使用全国地区数据，提交 `provinceCode/provinceName/cityCode/cityName/districtCode/districtName`。

## 用户端免登录接口（前端判断依据）
`/user/shop/status`、`/user/category/list`、`/user/dish/list`、`/user/setmeal/list`、`/user/setmeal/dish/*` 不需 token，其余均需。
